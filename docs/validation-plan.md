# 验证方案与阶段门槛

状态：未来实施的验收设计，当前没有执行结果。所有数据须关联源码修订、补丁摘要、配置、ABI、构建模式、宿主版本及设备信息。

## 1. 比较口径

至少比较 upstream-reference bundled、compat-lite bundled、compat-lite external。content-lite 加入后，另与同配置的 bundled/external 配对比较。均使用同源码修订、ABI、优化等级、页面集和设备；测试前固定缓存、profile、联网和后台应用条件。

动态模式必须同时报告基础 APK 与完整内核包，不能把延后交付的字节描述为已经删除。静态 SDK 的总下载量和 external 首次完整可用下载量分别报告；资源压缩方式不同产生的差异要注明。

## 2. 指标定义

| 指标 | 测量方式与口径 | 评审规则 |
| --- | --- | --- |
| AAR 与基础 APK | archive 文件清单与长度；报告压缩/解压两种大小 | 区分 SDK 体积和空宿主基础成本 |
| 完整可用下载量 | 宿主增量包体 + 为首次运行取得的全部必要内核字节 | 不隐藏 external 内核包 |
| 稳态安装占用 | 应用、native、Gecko 资源、注册表分别统计，用户 profile 另列 | bundled 不重复保存一份 ZIP；external 不把签名包和展开内容永久重复保存 |
| 更新峰值空间 | 当前包 + 保留旧包 + staging + 临时输入 + metadata | 安装前预估上限，空间不足拒绝安装且保留旧包 |
| 内存 | 对真实进程树采样 `dumpsys meminfo`；以 PSS 为主，RSS 辅助，注明共享计数口径 | 记录父进程、content、socket、GPU 等；只测宿主不算完成 |
| 初始化时间 | 单调时钟：初始化请求到 Runtime 就绪 | external 区分首次安装、已安装冷启动和进程已启动情况 |
| 首屏 | 本地固定页面可观测首帧/首绘，附录屏或性能 trace | 不把网络耗时混入装载开销 |
| 关闭后内存 | 关闭 Session 后与承载进程退出后分别测量 | 不宣称关闭页面等于卸载 native |
| 稳定性 | 启动循环、前后台、内容崩溃和进程恢复 | 按 packageId/buildId 归因，不把网站内容崩溃全部算包损坏 |

M0 建议每个条件至少 30 次启动，报告中位数与 P95、分布和失败次数；内存报告统一稳定窗口与负载。噪声较大时增加样本，不仅挑选最快值。

### 候选性能门槛

这些是供 M0 评审的初始工程预算，不是用户已确认的硬指标，也不是当前测试结果：

- compat-lite 裁剪应有可归因的字节减少；不事先承诺固定 MB 或固定百分比。
- external 相对同配置 bundled，在已安装包、相同冷缓存条件下，Runtime 就绪 P95 回归暂定不超过 10%，稳定窗口进程树 PSS 回归暂定不超过 5%。两项均同时报告绝对差值；M0 根据基线与设备噪声校正后冻结。
- 任意保留功能的确定性本地验收不得新增失败；目标网站回归要区分裁剪导致的不支持、上游本身不支持与实现缺陷。
- 兼容、安全和恢复门槛先于性能预算；不以移除隔离来满足预算。

## 3. 平台与装载矩阵

| 维度 | 首期必测 |
| --- | --- |
| Android | API 26 下限、API 34 动态代码约束环境、API 35 的 4 KB/16 KB 环境、锁定 targetSdk 对应系统；同一环境可覆盖多个条件 |
| ABI | arm64-v8a 发布；x86_64 测试。不用 x86_64 结果替代 arm64 实机验证 |
| 设备 | 一台有代表性的低内存设备与一台主流设备；16 KB 环境另行验证 |
| 模式 | bundled、external；静态包中不引入 external 依赖 |
| Crash reporter | 保留/移除分别验证 bundled 与 external；覆盖最终配置支持矩阵，并分别报告体积差值 |
| 进程 | 所有实际启用的进程类型、内容进程重建、isolated/zygote 模式；不支持的模式须明确列出且不能较基线降低安全边界 |
| 资源 | CSS/JS 模块、内置 Gecko 页面、注册资源、locale、图片、字体回退，主子进程一致 |
| 装载链 | 首次 mozglue、NSS/SQLite、XUL、JNI、动态依赖、linker namespace、错误 ABI 与缺库 |

16 KB 测试需要记录实际 page size、检查每个 ELF 的 segment 对齐，并验证打包后的实际加载。不能只验证链接器参数或只看包能解压。

## 4. 页面与嵌入行为

确定性本地页面至少覆盖 HTML/CSS 布局、Flex/Grid、中文/英文/emoji、JS 模块、Wasm、Canvas/WebGL、图片、输入法/选区、剪贴板交互、无障碍、Cookie、IndexedDB、localStorage、Service Worker、历史导航、多窗口请求、前后台与旋转。

涉及来源或网络语义的页面由测试宿主或本地测试服务提供，避免随意使用 `file://` 替代安全上下文。测试 fixtures 不保存真实业务站点账号、访问记录或渠道地址。

媒体、WebRTC、PDF、HLS、语音及扩展按 capabilityProfile 区分：保留则测试功能，删除则测试能力查询及可预期的不支持行为。普通 HTTPS、证书错误、权限拒绝、文件选择和下载委托也要覆盖。实际目标网站由接入方提供后形成独立清单，不能以本地 smoke test 代替全部网页兼容性。

Crash reporter 单独对照同修订、同 release 优化等级的保留/移除构建：检查 `MOZ_CRASHREPORTER`、ELF/链接依赖、包文件、合并 Manifest、crashhelper 服务和 Java/JNI 引用；有残留时解释其用途或补充裁剪，不能只看是否停止上传。移除产物应明确不提供 Gecko reporter 的 minidump 与相关回调；能力摘要、桥接与服务契约必须匹配。另以受控异常退出验证健康检查、失败计数及旧包恢复不依赖报告文件或 reporter 回调。系统自身可能生成日志或 tombstone，不要求将这些系统诊断能力一起删除。

## 5. 安装与故障注入

| 场景 | 必须达到的结果 |
| --- | --- |
| bundled 首次安装、断网、重启 | 不触发 external 包准备即可使用 |
| external 没有包、来源流中断或取消 | 返回明确状态，不留下可激活半包 |
| 签名错误、未知 keyId、文件被篡改 | 在首次 native 执行前拒绝 |
| 签名正确但桥接指纹/服务协议/ABI/API/能力不匹配 | 拒绝，不只比较版本号 |
| ZIP 穿越、重复条目、符号链接、解压超限 | 安全拒绝，无安装目录外写入 |
| 安装中应用被杀、磁盘写失败 | 下次启动仍选择旧健康包，清理无效 staging |
| 多线程、多进程并发安装与选择 | 同包去重，注册事务一致，运行版本不漂移 |
| 安装新包时仍有旧 Runtime/子进程 | 新包保持 PENDING，旧进程树持续使用原包 |
| 主进程崩溃、旧子进程尚存 | 新 Runtime 启动前处理旧租约/进程，不发生同树混载 |
| 子进程被系统重建 | 继承所属 Runtime 的包和访问句柄，不读取“最新包” |
| 孤立进程读不到私有路径、zygote 过早预加载 | 通过已验证的受控访问机制解决；无法解决则 external 不通过门槛 |
| 新包初始化失败、两次启动失败，含移除 reporter 后的早期异常退出 | 用独立启动标记、握手、进程死亡通知和超时记录；隔离候选，只回退到兼容且不低于安全下限的健康包；未知退出原因不伪称已确认 native 崩溃 |
| 已识别的用户取消或系统回收 | 不判为包损坏；无 reporter 时也不能把所有进程退出直接归因于内核缺陷 |
| 普通网站单次崩溃 | 按内容崩溃处理，不自动隔离整个内核 |
| profile 已被新版本迁移 | 不自动交给旧内核，返回需要恢复策略的状态 |
| 回收器遇到 active/pending/租约持有包 | 保留，不删除仍被使用的 native 与资源 |
| 切换 bundled/external 接入方式 | 通过应用重新构建发布，核对 profile 兼容；不在活跃进程中临时切换 |

候选健康检查仅在 `:corecheck` 进程的临时 profile 上运行；验证它与正式 Runtime 不并行使用同一 Gecko 服务池，自检结束后整个测试进程树退出，再启动正式 Runtime。不能在同一个进程先关闭测试 Runtime 再重建正式 Runtime。验证阶段还需证明正式 profile 在候选自检前未被打开，避免“回退包可加载但用户数据已经不兼容”。
